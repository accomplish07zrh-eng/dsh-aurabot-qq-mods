# 记忆（向量版）

替换 Aurabot 内置的「记忆」模块：整套记忆逻辑搬过来，检索再拼一路本地向量，**名额一半给关键词、一半给向量**。读写仍然是同一份 `memories.json`，卸载后自动回到内置记忆。

| 项 | 数值 |
|---|---|
| 市场包内 | 只有源码和词表（约 150KB），不含模型和运行时 |
| 首次自取 | `model_int8.onnx` 约 23MB + onnxruntime tgz 约 115MB，解压后只留 Windows x64 文件 |
| 解开后占盘 | 约 55MB |
| 平台 | 只支持 Windows x64（其它平台缺少 `onnxruntime.dll`，会退化为纯关键词检索） |
| 推理 | CPU，单句 1~2 毫秒（第一次加载模型约 50 毫秒） |
| 网络 | 仅首次补齐缺失的模型/运行时；补齐后纯离线 |

## 安装

插件 1.2.0 起支持模块市场：打开 Aurabot 面板的「模块市场」，找到「记忆（向量版）」，确认「会替换内置记忆」的提示后安装。

- 它和内置 `memory` 同 id，安装时会替换内置模块，原设置会自动迁移；停用或卸载后内置记忆恢复。
- 装好后建议再装「记忆中枢」：向量、联想、每日读写的调节界面都在中枢面板的「记忆增强」页签里；只装本模块时按默认参数运行。
- 首次启动会联网补齐 `model_int8.onnx` 和 onnxruntime，之后不再联网。日志里会看到下载进度和 `[记忆向量] 算完 …`。
- 手动安装：把 `memory` 文件夹放进 Aurabot 数据目录的 `modules\` 下，通常是
  `%USERPROFILE%\.dsh\plugins-data\aurabot\modules\memory`。

### 首次会访问的地址

依次尝试，任意一个成功即停止：

- 模型：`https://modelscope.cn/...`、`https://hf-mirror.com/...`、`https://huggingface.co/Xenova/bge-small-zh-v1.5/resolve/main/onnx/model_int8.onnx`
- 运行时：`https://registry.npmmirror.com/onnxruntime-node/-/onnxruntime-node-1.31.1.tgz`、`https://registry.npmjs.org/onnxruntime-node/-/onnxruntime-node-1.31.1.tgz`

除上述下载外不访问任何外部地址，不发送记忆正文。

## 检索怎么算（对半分）

聊天时那道「你记得这些事」提示，是内置的 4 条关键词结果，再让向量最多补 2 条；工具 `recall_memory` 取 8 条；别的模块调 `recall()` 时跟内置 `memory.recallCount`（默认 6）走。合并检索（`recallWithCache`）的规则：

1. 一半名额（`limit / 2`，默认 6 条时是 3 条）从原来的关键词检索里取，保证名字、QQ 号、专有说法这类字面对得上的命中。
2. 另一半从向量检索里取，并且排除前面已经选中的。
3. 任一边不够就用另一边补满。
4. 重要度 0.8 以上、又确实沾边的，保送一条到最前面。

两边各自排序，**没有「相似度权重」这个参数**：关键词那半沿用内置 BM25 分，向量那半直接用余弦相似度，不把两种分数线性相加。纯用向量时短句、指代词多的区分力弱，所以保留一半字面名额。

## 装完会发生什么

1. 启动约 5 秒后开始给现有记忆算向量（几百条大约 1~2 秒算完，日志里有 `[记忆向量] 算完 …`）。
2. 之后每分钟核对一次：新记的、被内置整理改写过的条目补算；记忆库里已经删掉的，索引跟着删。
3. 每轮聊天前，先在这轮 `prompt` 里把这句话算成向量，当轮检索直接用它；同步的 `recall` 如果拿不到新向量，就退回纯关键词。

## 怎么调

装好「记忆中枢」后，Aurabot 侧栏会多一页「记忆中枢」，向量、联想和每日读写都在这一页，用「记忆向量 / 记忆联想 / 每日读写」三个页签切换。向量这半的调节项：

| 项 | 说明 |
|---|---|
| 按意思找 | 总开关，关掉就只用原来的字面检索 |
| 相似度门槛 | 0.1~0.95，默认 0.42。低于这个不算想起来，调高更保守 |
| 每轮提示补几条 | 向量额外补进「你记得这些事」的条数，0~4，默认 2 |
| 每轮最多想起几条 | 内置记忆的总条数，默认 6；向量那半按一半分名额 |
| 检索测试 | 输入一句话，同时看关键词、向量、合并后的三组结果 |
| 补算缺的 / 全部重算 | 换了模型或怀疑索引不全时用；平时每分钟会自动补 |

### 名字联想（页签）

| 项 | 说明 |
|---|---|
| 联想总开关 | 名字联想总开关 |
| 名字联想概率 | 0~100%，100 = 每次认出名字都联想；调低省 token |
| 问题联想 | 没认出名字时，也把问句的向量近邻当种子走一跳 |
| 问题联想概率 | 0~100%，默认 60%，只在没认出名字时生效 |
| 问题联想门槛 | 问句向量相似度门槛，默认 0.5 |
| 问题联想最多几条 | 0~4，默认 2；0 = 只查不补 |
| 最多走几步 | 1 = 直接相关 + 一跳；2 = 再顺关系走一步 |
| 每轮最多几条 | 名字联想 3~8，默认 5 |
| 联想门槛 | 默认 0.35，越高越保守 |
| 串联加深记忆 / 强化强度 | 被联想的条目按遗忘曲线回写，每条每天最多一次 |
| 主人额外称呼 / 她的额外称呼 / 额外实体 | 换部署时填自己的叫法；额外实体用分号分实体、逗号分别名 |
| 试一句 | 输入名字或问题，看认出谁、关联到什么、这次会强化几条 |

也可以用接口：

```
GET  /aurabot/api/vector/state
POST /aurabot/api/vector/rebuild   { "force": true }
GET  /aurabot/api/vector/try?q=备份传哪
```

`/vector/try` 会把「只有关键词找到的」「只有向量找到的」「合并后的」三组都列出来，调门槛时看这个。上面这些接口都在 `/aurabot/api/vector/*`；侧栏「记忆中枢」页走 `/aurabot/api/ext/memory-constellation/vector/*`，由该页转给记忆模块，没有另开一套别名。

## 模型

`model_int8.onnx`（首次启动下载）：**BAAI/bge-small-zh-v1.5** 的 int8 量化 ONNX 版，512 维，MIT 许可。
出处：<https://huggingface.co/BAAI/bge-small-zh-v1.5>
转换版参考：<https://huggingface.co/Xenova/bge-small-zh-v1.5>（`onnx/model_int8.onnx`，本模块直接用了这份转换结果）

用法按 BAAI 官方说明：取 `[CLS]` 位做句向量，再 L2 归一化，用点积（等于余弦）比相似度。

词表随模块分发：`assets/vocab.txt`，分词器（BERT WordPiece）在 `lib/embed.mjs` 里用 JS 重写，没有用 Python 那套 tokenizers。

## 索引文件

`plugins-data/aurabot/modules-data/memory/vectors.json`，只存 id → 512 个 float（base64）和条目的改写时间签名。
它只是副本，删掉会自动重建；记忆本身的增删改仍然只写 `plugins-data/aurabot/memories.json`。

## 运行时要什么

`node_modules/onnxruntime-node`（MIT），首次启动从镜像下载，只保留 Windows x64 的 `onnxruntime.dll`，删掉了 DirectML / dxcompiler 和其它平台的二进制。CPU 就能跑：单句 1~2 毫秒。

## 数据与隐私

- 声明能力：`network`、`filesystem`、`plugin-config`、`plugin-internals`；替换内置 `memory` 模块。
- 读取：内置记忆条目、Aurabot 配置里的 `memory` 设置。
- 写入：`memories.json`（沿用内置记忆的增删改）、`modules-data\memory\vectors.json`（向量副本）、Aurabot 配置里的记忆设置。
- 除首次下载模型/运行时外不联网，不发送记忆正文，不需要 API Key。
- 模块包里不含任何人的配置、记忆、日志或模型文件。

## 给别的用户部署

联想不再写死某套部署的称呼：

- 主人：从配置里的 `ownerName` / `ownerQQ` 自动取，另外自动加「主人」；
- 她自己的名字：从当前人格名自动取；
- 其他称呼：在「记忆中枢」→「记忆联想」页签填「主人额外称呼」「她的额外称呼」；
- 项目、朋友、约定的名字：填「额外实体」，格式 `项目甲,甲项目;朋友乙`——分号分实体，逗号分同一实体的别名；
- 记忆正文里被「」/“”括起来、出现两次以上的名字也会自动进别名表。

装两个模块就够：

1. `memory`（本模块）：替换内置记忆，带向量检索和 `reinforce`；
2. `memory-constellation`（显示名「记忆中枢」）：星图 + 向量 + 联想 + 每日读写，一页三页签。

数据都在 `~/.dsh/plugins-data/aurabot` 下，每个用户各自独立，不会串库。仍然要求 Windows x64；模型或运行时缺失时首次启动会自取。

## 已知的坑

- 向量只能「找到」，找到的东西对不对还得看门槛；问句很短（四个字以内）时相似度都挤在 0.5~0.7，容易捞进相邻话题的旧事。
- 换模型必须「全部重算」，不然新旧向量不在一个空间里，比出来是乱的。
- 向量额外多找出来的条目只进本轮提示，不会增加内置记忆的「被想起次数」，所以对遗忘曲线的加成比关键词命中小。
- `/vector/try` 是调试接口，它跑的那次关键词检索也会记进内置的「最近想起」并累加命中次数；调门槛时别反复刷同一个问句。
- 直接在面板里手写 `memories.json` 也要等下一次每分钟核对（或手动「补算缺的」）才会进向量索引。
- 首次安装如果下载失败，会退化成纯关键词检索，日志里有失败原因；网络恢复后重启或点「补算缺的」会重新尝试。
