# 网页挖数据（webdig）

让她自己去一个网站里翻数据：给一个网址，把页面**自带的**结构化数据、或者页面自己会去要的那几个公开接口地址挖出来，落盘成 json，回来告诉你在哪个文件、哪个字段有内容——而不是把整页 HTML 糊回上下文。

**纯读，只抓公开内容**：开跑先读 `robots.txt`，明文禁止的路径直接跳过；请求之间默认停 800ms；不碰登录态、不绕验证码、不伪装成别人。

## 用法

聊天里对她说「帮我看看这个站有什么」「能不能把这个站的东西挖下来」并给出网址，她会用 `qq_web_dig` 跑一轮。

或者面板里手动给网址跑。

## 它到底做什么

1. 读 `robots.txt`，记下禁止路径（后面每次请求都先过这道）。
2. 抓首页 HTML，取出内嵌数据 —— `ld+json`、`__NEXT_DATA__`、`__INITIAL_STATE__`、`window.__NUXT__` 这类。**这一步命中率最高**：很多站压根不用猜接口，页面自己就带着整份内容。
3. 扒首页引用的 JS，从里面找 `fetch(...)`、`axios.get(...)`、以及长得像 `xxx.json` / `/api/...` 的地址。
4. 把这些地址逐个抓一遍，能解析成 JSON 的就落盘，同时扫一遍「哪层是数组、有多少条、字段叫什么」。
5. 写一份 `summary.json`，里面是这次抓到的全部线索 + 注意事项。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `url` | 必填 | 完整 http(s) 网址 |
| `max` | 8 | 最多抓几个数据地址（上限 20） |
| `delay` | 800 | 每次请求间隔毫秒（下限 300，别调太低） |

## 落盘在哪

`<模块数据目录>/out/<时间戳>/`，里面有：

- `index.html` —— 首页原文
- `embedded-*.json` —— 页面内嵌的结构化数据
- `js-*` —— 扒下来的脚本
- `data-*` / `raw-*` —— 抓到的数据地址
- `summary.json` —— 汇总：哪些文件、哪层是数组、注意什么

## 它不做什么

- **不走登录态**：要登录才看得到的，抓不到就如实说抓不到。
- **不绕验证码**：首页里出现 `captcha` / 人机验证 / 访问过于频繁这类字样，`summary.json` 的 `notes` 会写明「这个站挡得太狠」，不会假装抓到了。
- **不跑浏览器**：只用 Node 自带能力发请求，跑不了 JS。所以「必须执行 JS 才渲染出内容」的站，它只能拿到骨架 —— 这种情况 `notes` 里也会写清楚。
- **不猜**：抓不到 JSON 就直说「没直接抓到 JSON，可能要跑 JS 或者数据在登录后面」。

## 已知限制

- 大站的接口常常要签名参数，地址挖到了也未必能直接取。挖到 `sign`、`token`、`signature` 这类参数基本就别抱希望。
- 有的站返回 3KB 的拦截页（内容看着像正常 HTML），`notes` 会标出「首页只有 N 字节，很可能是被反爬拦了」。
- 只跟同源地址。跨域的数据接口不抓。

## 兼容

`api: 1`，需要插件 `>= 1.2.0`。只用 Node 内置模块，没有 npm 依赖。
