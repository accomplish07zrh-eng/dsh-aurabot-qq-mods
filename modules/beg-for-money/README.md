# 讨饭

Aurabot 用户扩展。移植自 MaiBot 插件 [maibot-beg-for-money](https://github.com/Lbcheng1145/maibot-beg-for-money)（作者 Lbcheng1145，MIT）：群友提到打钱、请客、投喂、发红包时，让她伸手要一张收款码；讨完饭开一个道谢窗口，有人「打了」就让她按人格说句谢谢；顺手把收到的打赏记进本地账本 —— 群友说的金额只代表「他说他给了」，管理员私聊点头才算数。

> 仓库：[独立仓库](https://github.com/cdcp998/beg-for-money) · [模块市场](https://github.com/aureth-labs/dsh-aurabot-qq-mods) · 其他模块：[印象卡片](https://github.com/cdcp998/impression-card)、[价格监控](https://github.com/cdcp998/price-watch)

没有自动识别到账。个人收款码本身没有到账回调，原插件试过监听通知中心和截图 OCR 都走不通，所以这里也是「手动记账 + 口头确认」。

## 能做什么

| 功能 | 触发方式 |
| --- | --- |
| 讨饭 | `beg_for_money` 工具（对方提到请客 / 打钱 / 投喂 / 发红包时她自己调）/ `/讨饭` 命令，直接发一张收款码图片 |
| 道谢 | 讨饭后开一个窗口（默认 10 分钟），窗口内有人触发、或管理员手动 `/已打钱`，让她生成一句感谢发回原群 |
| 记账 | `record_payment` 工具 / `/打赏 15 [备注]` 命令。群友触发时不直接落账，先挂成待确认并私聊管理员 |
| 查账 | `check_ledger` 工具 / `/收款 [范围]` 命令，支持今天、昨天、全部、最近 N 天、指定日期 |

工具是给她主动调用的，命令是给人敲的，两者共用同一套底层逻辑。收款码一律用 `api.sendImage` 直接发图，不做合并转发 —— Aurabot 没有 `send.forward` 对应的能力。

## 为什么记账要过一道审批

个人收款码没有到账回调，谁都能顺口说一句「我转了」。如果直接落账，等于让任何一个群友往账本里写数字，而账本是纯手工维护的，记错了只能改文件。所以群友触发的记账不直接生效，而是挂成待确认、私聊问管理员；管理员 `/确认` 之后才真正记进账本、回原群道谢。

这条链路沿用原插件的做法：**先落盘再私聊**（私聊发不出去也不丢这一笔）、**先落账再删待确认**（账本没写进去就不会把待确认删掉）、**删不掉就回滚账本**（避免同一笔记两遍）。

```
群友说「我转了 15」
   ↓ 她调 record_payment
不直接记账 → 生成待确认 #1 → 私聊所有管理员
   ↓
群里回一句「这笔还没算数、已经报给管理员了（编号 1）」
   ↓ 管理员私聊 /确认 1
写进账本 → 在原群道谢 → 给打赏的人印象卡加「慷慨」
```

主人自己触发的记账不走这道手续，直接生效。

## 安装

需要 Aurabot 1.2.0 或更高版本（用户模块接口 1）。在 Aurabot 面板「扩展 → 模块市场」里搜「讨饭」安装即可，不用装 Node.js，也不用执行安装命令。

本地开发时在仓库里跑模块测试：

```sh
cd modules/beg-for-money
npm test
```

模块没有 npm 依赖，安装后代码在 `~/.dsh/plugins-data/aurabot/modules/beg-for-money`。设置和面板作为「系统」分组下的子标签页「讨饭」出现（用户模块默认落在系统组，模块定义里不写宿主不认的 `group` / `__panelGroup`）。数据（`ledger.json`、`approvals.json`）在 `modules-data/beg-for-money/`，升级代码不会清掉。

装完先去面板设置里填 `qrImagePath`。一行一个路径，可以放多张：

```
D:\收款码\微信.png
D:\收款码\支付宝.jpg
```

- 相对路径按扩展目录解析（`assets/qr.png` 就是模块目录下的 `assets/qr.png`），也可以直接填绝对路径；带空格、复制路径时带上的双引号都能认。
- 配了多张就**按顺序轮着发**：第一次发第一张、第二次第二张，避免每次都刷同一张图。
- 其中一张找不到时，好的那几张照常发，面板和回执会说明有几张没找到。全都没找到才算失败。
- 留空时讨饭直接回失败，日志会说明原因。

## 命令

`api.command` 只认主人，所以群友（以及 `adminQQ` 名单里的非主人管理员）的命令由扩展在 `message` 事件里接管（返回 `true` 就这条不再交给她回）。中文命令后面可以不加空格（`/打赏15` 也行）。

| 命令 | 谁能用 | 说明 |
| --- | --- | --- |
| `/讨饭` `/要饭` `/beg` | 所有人（`adminOnly` 开启后仅管理员） | 发收款码；同一聊天有冷却，每天有上限 |
| `/已打钱` `/打了` `/paid` | 同上 | 在道谢窗口内手动触发道谢 |
| `/打赏 15 [备注]` `/记账 15 [备注]` `/record` | 所有人 | 记账；群友触发且开了审批时只挂成待确认，不直接落账 |
| `/收款 [范围]` `/账本` `/收入` `/ledger` | 同上 | 查账；`adminOnly` 开启时群里只回「营收明细请私聊查」 |
| `/待确认` `/待审` `/pending` | 管理员，**仅私聊** | 列出待确认的记账 |
| `/确认 [编号]` `/同意` `/approve [编号]` | 管理员，**仅私聊** | 确认 → 真正记进账本、回原群道谢、给打赏的人加印象卡 |
| `/不记 [编号]` `/拒绝` `/忽略` `/reject [编号]` | 管理员，**仅私聊** | 丢弃这笔 |

`/收款` 的范围写法：留空（今天 + 最近 N 天 + 累计）、`今天`、`昨天`、`全部`、`7`（最近 7 天）、`2026-10-27`、`10-27`（今年 10 月 27 日，个位数不用补零）。

命令里不写编号时取最近一条待确认；面板的 `/approve` 接口例外，必须显式带编号和 `approve: true/false`。`/确认`、`/不记`、`/待确认` 只在私聊里受理 —— 那个列表里有群名、昵称和金额，群里发等于公开。非主人管理员只要在 `adminQQ` 名单里，也能私聊用这三条。

## 工具

| 工具 | 作用 |
| --- | --- |
| `beg_for_money` | 发一张收款码。对方提到请客、打钱、投喂、发红包时调；同一聊天冷却 + 每日上限 |
| `record_payment` | 对方说自己转了 / 打了钱并提到金额时调。群聊或别人私聊里触发走管理员确认；主人自己记直接生效 |
| `check_ledger` | 查账本，`scope` 支持今天 / 昨天 / 全部 / 最近 N 天 / 日期。只给主人（或管理员）用 |

`record_payment` 在群聊和别人的私聊里调起时一律按「需要管理员点头」处理 —— 模型能把任何字符串塞进参数，身份只认宿主注入的会话档位。群聊里「打赏人」取那个聊天最近说话的人（扩展自己从 `activity` 事件里记的），认不出来就不写，不会把「慷慨」加到别人头上。

## 设置

入口在面板的「系统」分组里（用户模块默认落在这里）。

这一页的**总开关就是设置表单里的 `enabled` 项**（改完点「保存设置」生效）。面板标题栏没有开关控件，所以面板里不会重复放第二个开关，只在关着时提示去设置表单打开。关掉后命令、她自己的工具、自动道谢都停，账本和待确认记录保留。

设置都在同一页里（模块的自动表单在上面，自定义面板在下面）。挑几个关键的：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | 开 | 总开关；关掉后命令、工具、自动道谢都停，账本和待确认记录保留（在设置表单里改） |
| `qrImagePath` | 空 | 收款码图片，**一行一个可以填多张**；相对路径按模块目录解析，也支持绝对路径（带空格 / 引号都行）。多张按顺序轮着发；部分找不到时好的照发并提示 |
| `senderName` | 大肥鱼 | 目前只用在私聊确认文案和备注署名上 |
| `cooldownSeconds` | 600 | 同一聊天两次讨饭的最小间隔 |
| `dailyLimit` | 3 | 每个聊天每天最多讨几次，`0` 不限 |
| `thanksWindowSeconds` | 600 | 讨饭后多久内算「可能有人打钱」的窗口，`0` 关闭自动道谢 |
| `thankIntent` | 「有人打了钱过来，去谢谢人家，别太肉麻，一两句就够」 | 交给 `api.ask`（带人格）生成道谢的意图，不是固定话术 |
| `adminOnly` | 关 | 开启后讨饭 / 已打钱 / 收款只给管理员 |
| `adminQQ` | 空 | 逗号或空格分隔；主人 QQ 自动算管理员 |
| `ledgerEnabled` | 开 | 记账总开关 |
| `currency` | 元 | 金额单位 |
| `recentDays` | 7 | `/收款` 默认展示最近几天 |
| `requireApproval` | 开 | 群友触发的记账要管理员私聊确认 |
| `approvalTimeoutSeconds` | 1800 | 待确认记录的有效期 |
| `approvalThrottleSeconds` | 30 | 同一聊天重复挂账的最小间隔，防刷屏 |
| `maxAmount` | 10000 | 单笔金额上限，超过直接拒绝 |
| `linkImpressionCard` | 开 | 确认后给打赏的人加印象卡 |
| `generosityDimension` | generosity | 加分的维度 key，默认「慷慨」 |
| `generosityDelta` | 1 | 每次加多少分 |
| `thankFallbackText` | 「谢谢你呀，收到了，我记着了。」 | 模型生成失败或返回空时直接发这句 |

## 和印象卡片的联动

确认记账 / 管理员直接记账之后，扩展会调 `api.use('impression-card')?.adjust(...)`，给打赏的人在「慷慨」维度上加一分（可调）。

这是**非强制依赖**：印象卡片没装、没开、或者那个维度被改掉了，**静默跳过**，只写一条 debug 日志。「慷慨」没加上完全不影响记账和道谢。扩展不 import 对方的文件，也不写死对方的数据结构 —— 拿不到就用 `?.` 什么都不做。

## 和参考插件的差异

| 参考插件（MaiBot） | 这里（Aurabot） |
| --- | --- |
| 收款码走 `send.forward` 合并转发 | `api.sendImage` 直接发图（Aurabot 没有合并转发能力） |
| 道谢靠 `maisaka.proactive.trigger` 唤醒 Planner | `api.ask`（人格塞进 system）问一句，`sendText` 发回原群；**不建 DSH 会话**；生成失败用兜底文案 |
| 命令对所有人生效 | `api.command` 只认主人，群友命令由扩展在 `message` 事件里接管 |
| 管理员只看 `admin_ids` | 主人 QQ 自动算管理员；工具路径用宿主注入的会话档位判断（主人私聊 = 全权限），不信任模型传的身份字段 |
| 记账确认：先落盘再私聊、先落账再删待确认、删不掉就回滚 | 同样的链路 |
| TOML 配置 / 账本常驻内存 | JSON（原子写）；账本解析失败时把坏文件改名留档并**禁止写盘**，避免用空账本覆盖历史 |

原插件的「手动记账 + 口头确认」这条底线没变 —— 依然不做自动到账识别。

## 安全边界

- **营收数据只在私聊**：`adminOnly` 开启后，群里的 `/收款` 只回一句「营收明细请私聊查」，`/待确认` / `/确认` / `/不记` 无论如何都只认私聊。账本列表里有群名、昵称和金额，群里发等于公开。
- **面板接口有闸**：`/state`、`/ledger`、`/approve`、`/beg` 全部只接受同源且来自本机回环的请求；`/approve`、`/beg` 只收 POST；`/approve` 必须显式带待确认编号和 `approve: true/false`，不能靠「不填就取最近一条」批准。`/state`、`/ledger` 响应里的管理员 QQ 已脱敏，不返回账本文件的绝对路径。
- **待确认文件也有损坏保护**：`approvals.json` 解析失败时改名为 `approvals.json.corrupt-<时间戳>` 留档，本次运行拒绝写回，避免下一次保存用「空列表 + 新记录」覆盖历史。
- **道谢限流**：同一个聊天两次道谢尝试至少隔 30 秒；窗口内无论生成 / 发送成败都只自动触发一次，失败后只允许手动 `/已打钱` 重试；message 和 activity 两条通道按消息 id / 文本去重。`api.ask` 8 秒超时，超时走 `thankFallbackText` 兜底，不会把聊天永久卡在「正在道谢」。
- **试运行（宿主 `dryRun`）**：账本照常写本地数据，但不会真往群里发消息；回执会明确写「试运行」，不会谎称「已在群里道谢」；`/讨饭` 按模拟成功处理，不回滚冷却 / 每日额度。
- **管理员身份**：主人 QQ 自动算管理员，名单里的其他 QQ 也可以，并且能在私聊里执行 `/确认` / `/不记` / `/待确认`；工具调用时只认宿主注入的会话档位，模型参数里的身份字段一律不采信。
- **收款码路径**：`qrImagePath` 指向本机文件，相对路径按模块目录解析；只认 png / jpg / gif / webp 且不超过 8MB，留空或全都找不到时讨饭直接不可用，不会发错图。
- **待确认会过期**：超过 `approvalTimeoutSeconds` 的记录失效，避免管理员很久以后才翻到一笔陈年旧账、记错月份。
- **道谢只发一句话**：走 `api.ask` 问一次，不建 DSH 会话、不进聊天记忆、不占工作区；输出的 HTML / markdown 图片 / 用不了的格式标签都会先清掉（模型偶尔会写 `<img src="emoj表情:偷乐"/>` 这种东西，原样发出去群友看到的就是一串标签）。能保留的只有 `<face:名字>`，交给中枢换成 QQ 小黄脸。
- **道谢不会把「反问」发出去**：提示词里把「谁、打了多少、钱已经收到了」写进用户消息（只给一句「写一句吧」会让模型反问「写啥啊，你倒是给个题」），system 里再明确禁止反问；万一它还是回了「写什么 / 给个题 / 你想让我说什么」这类没在道谢的话，就改用 `thankFallbackText`。
- 账本和待确认都只写本机数据目录；坏文件改名留档而不是清空重来（账本是 `ledger.json.corrupt-*`，待确认是 `approvals.json.corrupt-*`）。

## 测试

不联网、不上 QQ：

```sh
cd modules/beg-for-money
npm test
```

覆盖范围解析与账本统计、坏账本 / 坏待确认文件保护、打款说法识别（否定句不误伤）、待确认 → 确认 / 拒绝 → 道谢 → 联动加分的整条链路，以及面板接口的 POST / 同源 / 本机闸、管理员 QQ 脱敏、道谢限流与双通道去重、`api.ask` 超时兜底、`dryRun` 语义和非主人管理员的 `/确认`。
