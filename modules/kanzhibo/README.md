# 看直播 · kanzhibo

给 [Aurabot（大肥鱼 QQ 插件）](https://github.com/accomplish07zrh-eng/dsh-aurabot-qq) 用的扩展模块。
让大肥鱼在抖音直播间「挂着」，顺便把该做的事做掉。

- 扩展接口：v1（`api: 1`）
- 插件版本要求：>= 1.2.0
- 运行平台：Windows / macOS（要装有 Edge 或 Chrome；Node 需要全局 `WebSocket`，即 22+）

## 它干什么

1. **进直播间**：开一台**独立**的浏览器（自己的 profile，不动你平时用的那个），通过 CDP 挂进直播间。
   给直播间地址最稳；给主播主页（`douyin.com/user/...`）会自己找「直播中」点进去。
   已经在同一个直播间里就**不刷新**（刷新会把播放和评论都打断）。
2. **和「刷抖音」互斥**：进房期间把 `douyin.enabled` 关掉；离开直播间 / 关掉挂直播之后自动放回来
   （先晾 10 分钟，免得两个浏览器抢同一个 profile）。暂停状态写在 `state.json` 里，插件重启也不会让刷抖音一直关着。
3. **进房评论**：等页面真的渲染出评论框（有可见的 `textarea` / `contenteditable`）再发一条你定的评论，一天一次。
   真的鼠标点框 → `Input.insertText` → 点「发送」或回车 → 回读框里还有没有字来验证。
4. **续粉丝团灯牌**：先看「今日任务」面板里灯牌那行是不是「已完成 / 已送出 / 已领取 / 已点亮」，
   没送才点左上角的粉丝团，弹出面板后再点「赠送 / 点亮 / 续费」。送完再判定一次，确认了才记「今天送过」。
   当天同一个直播间确认送出过就直接跳过（不重复点、不刷日志）。
5. **送礼物 / 替你说话**（只在主人明说时才做）：开礼物面板 → 按名字找礼物 → 点赠送 →
   用「抖币余额变少 / 出现赠送成功提示 / 飘屏里有礼物名」三个里任意一个确认真的送出去了；
   页面弹充值或抖币不足就立刻停。

## 用法

QQ 里（只有主人能发）：

```
/看直播            状态
/看直播 状态       同状态
/看直播 开         打开挂直播并立刻进一次房
/看直播 关         关掉挂直播，把刷抖音放回来（浏览器窗口先留着）
/看直播 进         立刻进一次房
/看直播 收工       关掉浏览器，刷抖音晾 10 分钟再放开
/看直播 自检       体检单：浏览器、CDP、时段、刷抖音、今日评论/灯牌、打法、视口
/看直播 确认       半自动模式下：同意这一下（只能确认一次，90 秒内有效）
/看直播 取消       撤掉待确认，不动手
/看直播 待确认     现在有没有在等我点头的动作
/看直播 灯牌       手动再试一次灯牌（当天连挂 3 次被降级后用它恢复）
```

她自己在聊天里也能用（模型按需调用）：

| 工具 | 什么时候用 |
|---|---|
| `kanzhibo_enter` | 「去看直播」「去 XX 的直播间」「帮我挂着」 |
| `kanzhibo_status` | 「你在看什么直播」 |
| `kanzhibo_stop` | 「别看了」「关掉」「回来吧」 |
| `kanzhibo_gift` | 只有面板「QQ 私信送礼」打开、且是主人的私聊、他明确说了送什么时才用（灯牌不算礼物） |
| `kanzhibo_say` | 「在直播间说一句 XX」——原话照发，一个字不改 |

进房 / 停止 / 送礼 / 说话这四个是**真动作**（开浏览器、改配置、花抖币、用你的号发言），
只有「这一轮有主人说话」时才会挂给她；群里别人开口时她手上只有一个状态查询，而且那个状态不显示在看谁。

送礼另加一道锁：面板里的「QQ 私信送礼」默认**关着**，关着时连工具都不挂给她；打开后也只认主人的**私聊**，
群里（哪怕主人在）不会送。关着的时候你跟她说「送个小心心」，她会告诉你开关没开，而不是嘴上答应。

## 设置项（`config.json` 的 `ext.kanzhibo`）

| key | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | switch | `false` | 挂直播总开关 |
| `target` | text | `''` | 直播间地址或主播主页 |
| `checkSec` | number | `120` | 多久检查一次（30–1800 秒，改了立刻生效，不用重载） |
| `schedule` | switch | `false` | 只在指定时间段挂 |
| `startTime` / `endTime` | text | `20:00` / `23:30` | 24 小时制，支持跨午夜（`22:30`–`01:00`） |
| `liveCommentOn` | switch | `false` | 启用进房评论（默认关） |
| `liveComment` | textarea | `''` | 评论内容，多行只发第一行 |
| `commentDelaySec` | number | `8` | 进房后等几秒再发 |
| `renewBadge` | switch | `false` | 进房后送灯牌（**有误触风险**：见下面一节） |
| `badgeDelaySec` | number | `30` | 进房后等几秒才开始送（5–600）。越早越容易点偏 |
| `giftByDm` | switch | `false` | 允许在主人私聊里让她送礼（花抖币；群里永远不送） |
| `semiAuto` | switch | `true` | **半自动**：真按下去之前截图发私聊，等 /看直播 确认。关掉＝自动（照样过命中校验） |
| `confirmSec` | number | `90` | 等你点头多少秒（10–600）；到点没确认就自动撤销，不点 |
| `minuteReport` | switch | `false` | 进房时在 QQ 里说一声（调试用） |

面板顺序按「要不要挂 → 什么时候挂 → 挂谁 → 进房评论 → 灯牌 → 礼物 → 调试」排，长说明都在标签下面那行小字里；
自动表单底下还有一张「先说清楚：这两件事没有撤销」的卡片，写着误触风险和当前状态（只读，可刷新）。

## 面板怎么排的（0.4.1）

设置表单全在自定义面板里，按**大类分卡片**，从上到下：

1. **挂直播** —— 挂直播 / 只在时段内挂 / 时段 / 直播间或主页 / 多久看一次 / 进房时通知我
2. **进房评论** —— 开关 / 内容 / 等几秒
3. **粉丝团灯牌** —— 开关 / 等几秒（带误触提示）
4. **送礼（独立一大类）** —— 允许私信送礼 / 动作前先问我 / 等你多少秒 + 当前打法说明
5. **风险与现场** —— 灯牌误触、抖币花费
6. **现在是什么状态** —— 浏览器 / 目标 / 时段 / 刷抖音 / 今日评论灯牌 / 打法 / 待确认（可刷新）

实现上：模块定义里 `settings` 留空，字段清单放在 `settingsSchema`（自检脚本读它），
面板通过 `draftSettings` / `setSettings` 改草稿，所以底部「保存设置」、未保存提示、离开提醒都照旧。

## 怎么做到「不点错」（0.4.0）

三层，缺一层都不行：

1. **坐标系先钉死**：进房后把窗口拉到 1280×900、页面缩放归 1、prefers-reduced-motion=reduce，每次动手前复核一遍。
   坐标漂移是「今天行明天不行」的头号原因。
2. **找元素 + 四道闸门**：文字命中 → 映射到「最小可点祖先」→ 候选必须**唯一**（两个都像就放弃）→
   矩形要落在区域带里（灯牌：左上；礼物：面板内，并且**排除底部那条常驻礼物栏**——那一条点下去也会直接送）→
   9 点采样命中校验（被弹层或别的元素挡住就一律不点）。查找还支持**同源 iframe 和影子树**，
   因为抖音现在就把粉丝团面板塞在这两种结构里。
3. **真按之前先给你看**：semiAuto 打开时，把要按的位置框成红框截图发私聊，等你 /看直播 确认 才动手；
   90 秒不回自动撤；确认时会重新校验一次（元素签名变了就作废）；点完回读证据（今日任务 / 抖币余额 / 飘屏）。

另外：灯牌连续 3 次没成 → 当天降级成「提醒你自己点」，同一原因一天只提醒一次，不再空转。

排查 / 调试接口（默认只读；open=1 才会做不花钱的点击）：

    GET /aurabot/api/ext/kanzhibo/probe?what=info
    GET /aurabot/api/ext/kanzhibo/probe?what=text&q=点亮
    GET /aurabot/api/ext/kanzhibo/probe?what=badge&esc=1&open=1&shot=1
    GET /aurabot/api/ext/kanzhibo/probe?what=prep                  # 走一遍灯牌的「准备」，不点
    GET /aurabot/api/ext/kanzhibo/probe?what=prepgift&name=小心心   # 走一遍送礼的「准备」，不点
    GET /aurabot/api/ext/kanzhibo/pending

## 续灯牌为什么会点偏

它是在**真实页面上点真实坐标**（`Input.dispatchMouseEvent` + `el.click()`），不是调接口，
所以点哪儿全看当时的 DOM：页面没渲染完、抖音改版、窗口拉得很小、左上角临时盖了个弹层，
都可能点偏到顶栏、礼物栏、甚至别人的头像上。这不是「理论上可能」，是这套做法的固有代价。

现在能兜住的：

- 只认「文字短（≤24 字）、靠左上（top < 75% / left < 40%）、面积最小」的那个元素，先排掉把整页文字都包进去的大容器；
- 二次确认也只在左上那块面板里找「赠送 / 点亮 / 续费」，不碰底部礼物栏；
- 进房先等 `badgeDelaySec`（默认 30 秒）再动，越早越容易点偏；
- 点完回读「今日任务」里那一行：读不到「已完成 / 已送出」就不记成功，下一轮再来一次。

看到它在直播间里乱点，先把「续粉丝团灯牌」关掉，再去面板「日志」页看它到底点了什么（每次点击都会打一条「点了灯牌：…」）。

## 自检

```bash
node test/verify.mjs            # 74 项：注册、权限、送礼开关、时段、去重、崩溃恢复、选点/唯一性/签名、闸门、点击器、面板渲染
set LIVE=1 && node test/verify.mjs   # 再加 3 项：真起 Edge / CDP 连上 / 收工能关
```

脚本喂的是假 `api`：不发 QQ、不改真配置、数据落在临时目录。Windows 用 `set`，macOS/Linux 用 `LIVE=1 node ...`。

QQ 里 `/看直播 自检` 会给一份体检单；面板里也能调 `GET /aurabot/api/ext/kanzhibo/selfcheck`（JSON）。

## 会访问什么、会留下什么

| 访问目标 | 用途 |
|---|---|
| `https://live.douyin.com/…`、`https://www.douyin.com/user/…` | 进直播间、在主播主页找「直播中」、发评论、点灯牌 / 礼物 |
| `http://127.0.0.1:9300-9699/…` | 本机 CDP，只用来控制它自己启动的那台浏览器 |

除了上面这两类地址，不发任何其它网络请求；Cookie、聊天内容、账号信息都不会被发到别处。

在本机会做三件事：在 `modules-data/kanzhibo/live-profile/`（`api.dataDir()`）里放一个**独立**的浏览器 profile
（这里会有抖音登录态）、在 `state.json` 里记今天评论 / 灯牌做没做过、用 `api.setConfig` 改 `douyin.enabled` 这一个布尔值。

## 第一次用要手动登一次抖音

专用浏览器的 profile 在 `plugins-data/aurabot/modules-data/kanzhibo/live-profile/`，
是空账号。第一次让它进房后，在弹出的那个窗口里扫一下码登录——之后一直有效。
没登录也能看，但发评论、送灯牌、送礼都会失败（页面没有对应控件）。

## 它靠什么判断（改代码前先看这里）

| 判断 | 依据 |
|---|---|
| 在不在直播间 | `location.href` 以 `https://live.douyin.com/` 开头 |
| 页面加载完了 | 有可见的 `textarea` / `contenteditable`，或标题含「直播 / 直播间」 |
| 灯牌「今天送过了」 | 今日任务里「灯牌」+「已完成 / 已送出 / 已领取 / 已点亮」 |
| 评论发出去了 | 点完发送后回读输入框，还含有前 3 个字就算没成功 |
| 礼物送出去了 | 抖币余额变小 / 「赠送成功」提示 / 飘屏出现「礼物名 x N」 |
| 要充值了 | 页面出现「充值 / 抖币不足 / 余额不足 / 去充值」 |

找元素一律用「真实鼠标坐标点击」（`Input.dispatchMouseEvent`），因为直播间的面板多半按坐标判定，
`el.click()` 经常没反应。挑元素时优先**文字短、靠左上、面积最小**的那个——不加限制会点到顶部导航。

## 已知限制

- 抖音改版会换 DOM：找评论框、找「今日任务」、找粉丝团入口都可能失效，报错会写进面板「日志」页（按模块 id 分类）。
- 一台机器同一时间只挂一个直播间（一个 profile 一个窗口）。
- 送礼、发评论都是**用你自己的账号**在真实直播间里的真实动作，没有撤回；点灯牌还可能点偏（见上面那一节）。
- 不处理验证码：页面弹验证码时它只会失败并把原因说出来。
- 抖音现在有**几套直播间版式**（经典版 / 抖音精选外壳），面板可能在 iframe 或影子树里，礼物也可能是
  「点一下就直接送」。模块按「找不到就放弃、绝不盲点」处理；版式对不上时的表现是**没送成 + 日志说明原因**，
  而不是点错。真要看它卡在哪，用上面的 /probe 接口。
- 半自动默认开：不接受 90 秒内回确认，就会放弃这一轮（这是设计，不是故障）。
